# 序列解析器的诊断能力：一个 fasta 解析器为什么要报告 12 种警告

大多数解析器的契约是"要么成功返回数据，要么抛异常"。科研文件解析器不能用这个契约——**格式有问题的文件仍然包含有效数据，丢掉它才是错的**。

一个 MALDI 质谱仪导出的 FASTA 里有 3 条记录长度不一致，用户想看的可能就是前两条。一个 A3M 多序列比对里有非标准残基，那是 Clustal 注释，人眼完全能读。解析器的职责是**尽力提取 + 完整报告问题**，不是当门卫。

AtomOS 的 `SequenceParser.ts` 是这个思路的完整实现。

## 一、解析结果自带诊断信息

```typescript
export type SequenceDiagnostic = { index: number; char: string };
export type SequenceRecord = {
  ordinal?: number; id: string; description: string; header?: string; sequence: string;
  length?: number; alphabet?: SequenceAlphabet; invalid?: SequenceDiagnostic[]; empty?: boolean;
};
export type SequenceParseResult<T extends SequenceRecord = SequenceRecord> = {
  records: T[]; sourceLength: number; truncated: boolean; warnings: string[];
  totalLength: number; maxLength: number; minLength: number;
  alphabets: SequenceAlphabet[]; alignedLength?: number;
};
```

三个设计点：

1. **`invalid?: SequenceDiagnostic[]`** —— 非法字符带**位置索引和字符本身**，不只是"有问题"。UI 可以精确高亮第 847 位上的那个 `?`
2. **`warnings: string[]`** —— 顶层聚合警告数组，UI 可以一行行渲染
3. **`truncated: boolean` + `sourceLength`** —— 截断了要明说，还要说原始有多长，否则用户不知道看到的是全量还是切片

## 二、alphabet 判定：三字母集 + U 的启发

```typescript
const DNA = new Set("ACGTUN".split(""));
const RNA = new Set("ACGUN".split(""));
const PROTEIN = new Set("ABCDEFGHIKLMNPQRSTVWXYZOU".split(""));

function alphabetFor(sequence: string, invalid: SequenceDiagnostic[]): SequenceAlphabet {
  if (!sequence) return "unknown";
  if (invalid.length) return "mixed";
  const upper = sequence.toUpperCase();
  const dna = [...upper].every((char) => DNA.has(char));
  const rna = [...upper].every((char) => RNA.has(char));
  const protein = [...upper].every((char) => PROTEIN.has(char) || char === "-" || char === ".");
  if (dna && !upper.includes("U")) return "dna";
  if (rna && upper.includes("U")) return "rna";
  if (protein) return "protein";
  return "mixed";
}
```

**DNA 和 RNA 的字母表只差一个 U（尿嘧啶）**。所以判定不能简单匹配集合，要看实际内容：

- 全部字符都在 DNA 集合里，**且不含 U** → `dna`
- 全部字符都在 RNA 集合里，**且含 U** → `rna`
- 全部在蛋白集合里（含 `-` `.` 对齐字符）→ `protein`

那"只含 A/C/G 的序列"呢？判定成 DNA。**这在生物学上是错的**（ACGTN 也可能是蛋白），但 UI 上区分 DNA 还是 RNA 只影响计数单位和配色，实际影响可控。而把 A/C/G/T 的序列标成蛋白会更令人困惑——因为蛋白没有 T。这个启发式的取舍是"最可能的解释优先"。

注意蛋白字母表里**有 O 和 U 没有 J**：`ABCDEFGHIKLMNPQRSTVWXYZOU`——J 按惯例被排除（所有生物化学命名里 J 从来不用），塞进去会让拼写错误被静默接受。**把不可能的字符排除在合法集合外，是一种弱校验**。

## 三、非法字符诊断：位置 + 字符

```typescript
[...sequence].forEach((char, index) => {
  if (!/[A-Z*.\-]/iu.test(char)) invalid.push({ index, char });
});
```

两个细节：

**`[...sequence]` 而不是 `sequence.split("")`** —— 展开 Unicode 码点，正确处理代理对（emoji、某些特殊字符不会被切两半）

**`[A-Z*.\-]` 包含 `*`** —— `*` 是翻译终止符，在核酸序列里合法。漏掉它会把正常的终止密码子标成非法

正则带 `i` 标志，所以大小写都接受，但 `index` 是**原始字符串的下标**——UI 高亮时直接用。

## 四、警告生成：每种问题独立成条

```typescript
const warnings = records.flatMap((record) => [
  ...(record.empty ? [`empty sequence: ${record.id}`] : []),
  ...(record.invalid?.length ? [`invalid characters: ${record.id}`] : []),
  ...(msa && (record as MsaRecord).alignedLength !== alignedLength ? [`alignment width mismatch: ${record.id}`] : []),
]);
if (truncated) warnings.push("source truncated for preview");
```

三类警告 + 一条截断提示。用 `flatMap` 把条件展开成平铺数组——每条问题独立、可单独展示、可单独计数。

**alignment width mismatch 值得单说**：MSA（多序列比对）的定义就是所有序列等长。长度不一致意味着文件损坏或者根本不是 MSA。这个检查只在 MSA 模式下跑：

```typescript
const alignedLength = msa ? Math.max(0, ...records.map((record) => (record as MsaRecord).alignedLength ?? 0)) : undefined;
```

用最大值做参考宽度，然后和每条比对。如果大部分记录一致、少数不一致，警告精确指出了问题记录。

## 五、BOM 剥离和 maxChars 截断

```typescript
function parse(text: string, msa: boolean, maxChars = Number.POSITIVE_INFINITY): SequenceParseResult {
  const sourceLength = text.length;
  const truncated = sourceLength > maxChars;
  const source = text.replace(/^\uFEFF/u, "").slice(0, maxChars);
```

BOM 剥离放在截断**之前**——顺序反了的话，一个带 BOM 且超长的文件会浪费一个字符的截断额度，且 BOM 可能没被剥掉。

`sourceLength` 记录的是**剥离 BOM 之前**的长度——这是用户文件真实的字节数，UI 提示"显示 X / 共 Y 字符"时要用它。

maxChars 默认无穷大，调用方按需限制。这是"解析器不做策略决定"的分工——**截断多少是视图层的事**。

## 六、MSA 特有字段：缺口统计

```typescript
const insertCount = (sequence.match(/[a-z]/gu) ?? []).length;
const gapCount = (sequence.match(/[-.]/gu) ?? []).length;
return { ...base, alignedLength: sequence.length, gapCount, insertCount, inserts: insertCount };
```

MSA 有两个普通 FASTA 没有的量：

- **gapCount**（`-` 和 `.`）——该序列在这一列是缺口
- **insertCount**（小写字母）——A3M 格式里的小写代表**插入残基**（相对于参考序列的额外内容）。这是 A3M 相对 FASTA 的核心扩展

统计这两个值，前端就能做**比对质量概览**：某条序列缺口特别多，可能是质量差的片段；小写插入特别多，可能是不同的可变区剪接变体。

## 七、sequenceBlocks：十残基单位

```typescript
/** Split a sequence into the fixed ten-residue units used by both viewers. */
export function sequenceBlocks(sequence: string, blockSize = 10): SequenceBlock[] {
  if (blockSize < 1) throw new Error("blockSize must be positive");
  const blocks: SequenceBlock[] = [];
  for (let offset = 0; offset < sequence.length; offset += blockSize) {
    const text = sequence.slice(offset, offset + blockSize);
    blocks.push({ start: offset + 1, end: offset + text.length, text });
  }
  return blocks;
}
```

序列查看器按 10 残基一格排版（生物信息学界的传统排版，和测序读长的分组习惯一致）。两个细节：

- **`start` 是 1-based**（`offset + 1`）——序列位置在生物学里从 1 开始编号，UI 直接显示不用转换
- **`throw` 校验 blockSize** —— 防御性检查，blockSize ≤ 0 会导致死循环

## 八、isMsaFilename：扩展名判定

```typescript
export function isMsaFilename(name: string): boolean {
  return /\.(?:a3m|aln)$/iu.test(name);
}
```

`.a3m` 是 A3M 格式的标准扩展名，`.aln` 是比对文件的通用约定。`i` 标志让 `.A3M`/`.ALN` 也命中。

这个函数和 `rendererRegistry.ts` 里的扩展名集合配合，构成**先看名字再看内容**的分派链（下一篇讲）。

## 九、总结

1. **解析器返回数据 + 诊断，不返回"数据或异常"**——有问题的文件仍然有可用的部分
2. **诊断带位置**：`SequenceDiagnostic {index, char}` 支撑 UI 精确高亮
3. **alphabet 靠实际内容判定**：DNA/RNA 只差 U，靠"是否含 U"区分
4. **非法字符的合法白名单**：`*` 是终止密码子必须收，J 从来不用可以排除
5. **BOM 剥离在截断之前**，sourceLength 记录真实长度
6. **MSA 的量单独算**：gapCount 和小写 insertCount 是比对特有的信息
7. **策略不下放到解析器**：maxChars 由调用方决定，解析器只忠实报告

一句话：**科研数据解析器的品质不看它拒绝了多少坏文件，看它能否在坏文件里救出好数据，并且诚实地告诉你救出了什么、丢了什么。**
